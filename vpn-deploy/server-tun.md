# 国内主机 TUN 分支

国内 VPS 自身需要透明分流，或维护已有服务器 TUN 时读取。公共 HY2 网关应先在不开 TUN 时验证；已有 TUN 先检查，不用模板重置。

## 前提与配置

- 核查 `/dev/net/tun`、真实 NET_ADMIN 能力、现有容器网络、双栈路由、实际 SSH/远程服务端口和策略规则冲突。
- 私有备份路由、规则、防火墙及 DNS，记录 resolver 符号链接。保留云控制台或独立定时回退，约四分钟后无人操作也能停止代理。
- `tun.enable` 交给当前项目原生状态管理，配套 mixin 故意不包含它。新机先关闭，显式代理通过后再用项目当前支持的命令开启。
- 模板意图为 gVisor、auto-route、strict-route、关闭 auto-redirect、TCP/UDP 53 接管。按最新版稳定内核核对支持及实际行为，不因字段被接受就宣称全覆盖。
- 内核 IPv6 接管与 DNS AAAA 是两件事。模板保留前者、抑制普通 AAAA；硬编码国外 IPv6 也应被接管或拒绝，不能绕过。

## 路由所有权

AI 为当前安装生成小型幂等 add/del helper 与 systemd drop-in。选择未占用的标记/优先级，核实核心实际 TUN 表。下列只是示例编号，不是全局保留值：

| 示例 | 精确用途 |
| --- | --- |
| mark `6666`，优先级 `8890` | `fwmark 6666 lookup main`；标记与渲染配置一致 |
| 优先级 `8900` | `ipproto tcp sport <实际SSH端口> lookup main` |
| 优先级 `8901/8902` | 仅现场必要远程服务的 TCP/UDP 源端口回包范围 |
| 优先级 `8903` | 仅启用了可选 SOCKS5 时，保护其 TCP 源端口回包 |
| 优先级 `8904` | `ipproto udp sport <CN_PORT> lookup main`，保护 HY2 回复 |
| 优先级 `8990`，表 `2022` | `iif lo lookup <实际TUN表>`，不是无条件 `from all` |

按现场需要添加并验证 IPv4/IPv6 两套规则。add 只拥有精确匹配，del 只删这些匹配，不清空通用防火墙/策略规则。启动钩子 add、停止钩子 del，UMask0077；回退旧 helper 前先由当前版本清理其全部自有规则。

Mihomo 业务规则用 `AND,((IN-TYPE,TUN),(SRC-PORT,<端口或范围>)),DIRECT` 保护已有服务，插在公共入口拒绝之后、普通主机分流之前。它与 Linux 源端口策略规则不同；公共代理客户端不能因使用相同源端口就取得直连路径。

## 完成条件

1. 启动自动回退，用当前项目原生命令开 TUN，核查双栈规则/表/网卡；避免持久环境代理变量重复接管。
2. 新建 SSH，验证原有服务与认证公共入口回复。
3. 清除显式代理/环境影响测试国内外出口。`curl --noproxy '*'` 排除显式代理但不会绕过 TUN。
4. 测国外 IPv6 字面地址并抓物理网卡；上游不可达可以失败，但不能直连目标。
5. 复测 DNS、公共入口私网/元数据拒绝、停止清理及重新生成后的持久化，全部正常后才撤销临时回退。

容器、自建命名空间、显式绑定物理网卡的程序需另测。停止代理不等于防火墙 kill switch，本分支不承诺服务停止后仍阻止直连。
