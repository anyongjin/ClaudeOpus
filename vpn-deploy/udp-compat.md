# 住宅 SOCKS5 UDP 兼容分支

仅在住宅套餐声称支持 UDP、真实 UDP 往返却失败时读取。安装最新版稳定内核不能代替检查；套餐只支持 TCP 则保留 `RES_UDP_SUPPORTED=false` 并说明限制，不为“修复”而绕过住宅出站。

## 按层定位

1. 从美国 VPS 独立测试同一 SOCKS5 的认证、UDP ASSOCIATE 和实际 UDP DNS 请求；控制握手成功不代表收到数据返回。
2. 对比完整代理链与隔离客户端直连住宅代理，使用独立状态目录/端口，不干扰正式服务。
3. 只检查响应状态、地址族、中继地址/端口等元数据；不记录用户名密码交换、完整认证抓包或原始配置。
4. 返回 `0.0.0.0`/`::` 时检查所装稳定版的归一行为。若直接作为 UDP 目的地址，可能发向本机而非上游。
5. 返回明确中继地址时必须保留；供应商多后端时，UDP 关联应属于与 TCP 控制连接相同的端点。

## 确认根因后才修补

优先用已验证包含等效处理的官方稳定版。最新稳定版仍在此场景失败时，对该稳定源码做最小局部兼容处理：

```go
// UDP ASSOCIATE 成功后、连接中继前；仅为语义示例。
if response.Bind.Addr.IsUnspecified() {
    response.Bind.Addr = M.SocksaddrFromNet(tcpConn.RemoteAddr()).Addr
}
```

这是 SOCKS 客户端依赖中的语义要求，不保证未来源码仍用同样标识符。只替换未指定地址，保留返回端口；用实际 TCP 对端 IP，不重新解析域名。不改成美国 VPS DIRECT。

AI 的构建与交付要求：

1. 取得所选最新稳定 sing-box 源码与实际依赖图，读取其工具链要求，不写死 Go 版本。
2. 在独立目录复制待修依赖，通过本地模块替换构建，不修改共享模块缓存。
3. 写三个带真实 UDP 返回的模拟 SOCKS 回归：未指定 IPv4、未指定 IPv6、显式指定不同中继地址。先证明原实现失败，再证明修复后通过且显式地址不变，运行对应包静态检查。
4. 用该稳定源码所需 Linux 标签构建，包含 HY2/SOCKS 能力；在用户私有 manifest 记录上游版本、源码/依赖hash、补丁、工具链、标签、测试与二进制hash。
5. 先隔离进程直测真实住宅上游，再备份并受控替换正式二进制，保留配置校验和与有界自动回退；只改二进制时回退不覆盖用户后来改动的配置。
6. 确认正式进程实际使用新二进制，复测整链 TCP、应用 UDP、认证和住宅出口，成功后撤销临时回退。

不要求复制任何旧用户的私有二进制、补丁目录或 manifest。此次新生成的补丁和回归测试随本用户运维包交付；未来升级重做回归，版本号更高本身不是证明。

官方参考：[SOCKS 出站](https://sing-box.sagernet.org/configuration/outbound/socks/)、[sing-box 源码](https://github.com/SagerNet/sing-box)、[SOCKS 依赖](https://github.com/SagerNet/sing)。
